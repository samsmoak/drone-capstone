BRIDGE  (every cross-surface relationship runs through it)
  Two, by design (CLAUDE.md, "The constraint everything follows from"):
  • Supabase — the web app and the agent never talk directly for autonomous
    work: browser -> Supabase -> agent polls -> radio. Tables + RLS are the
    contract (backend/supabase/migrations/).
  • The agent's local HTTP/WebSocket API — the desktop app (and the browser on
    the same network) -> backend/agent/cropwatcher/api/ -> radio. Manual control
    needs 50 Hz, so it never goes through the cloud.

CALL CHAIN  (UI element -> server)
  web:      page/component -> web/lib/queries.ts (reads, server-only + cache) or
            web/lib/mutations.ts (writes) -> Supabase. Never createClient() in a
            component.
  desktop:  page/component -> desktop/src/lib/agent.ts (api.*, Tauri invoke for
            the port and token) -> agent REST/WS in backend/agent/cropwatcher/api/
  agent:    api/ -> flight/ -> cflib -> Crazyradio -> drone

GATES  (CLAUDE.md "Commands"; report pass / fail / skipped for each)

CONVENTIONS  (CLAUDE.md "Conventions" is the full text)
  units      metres and seconds internally, everywhere; feet only in UI labels,
             converted at the boundary. Temperature stored in the unit the
             operator chose, with the unit recorded in the row. No money.
  errors     the agent returns errors as readable words the window can show
             (PR #63); never a raw driver or database error.
  auth       Supabase Auth (email + Google). Authorization is server-side: RLS
             on every table. Client checks are UX only — the app is public and
             commands a physical drone.
  theming    CSS custom properties on :root in web/app/globals.css (and the
             desktop's styles.css); raw hex only inside token definitions.
  state      Zustand holds only ephemeral live state; persistent data comes
             from Supabase.
