FLIGHT LOG — what was flown, what it measured, what changed because of it
=========================================================================

WHAT THIS IS

A running record of lab sessions, newest FIRST. It is the one doc in this tree
that is deliberately a journal: the feature docs describe the system as it is
now, git records how it got there, and this records WHAT THE DRONE ACTUALLY
DID — the readings, the failures, and which of them turned into a rule.

It exists because flight work cannot be re-run. A test that tumbles at 11.6 s
is gone; the only thing that survives is what was written down about it. Three
separate sessions were spent re-discovering the same facts before this file.

HOW TO ADD A SESSION

Add a block at the top, under the date. Record:

  CONDITIONS   battery, stations received, geometry age, tuning in force
  DID          the command, verbatim, so it can be repeated
  MEASURED     numbers, not impressions. "hopped" is not a measurement
  MEANT        what the numbers say
  CHANGED      the commit, or "nothing — still open"

A number with no units is not a measurement. A conclusion with no number is an
opinion. When something is not known, write "not measured" rather than
guessing — a guessed threshold has already cost this project flights.

THE LADDER

Nothing skips a rung. Each one is only run once the one above it passed, and
each is a separate power cycle if the one above it ended badly.

  0  cropwatcher check              every gate, no motors
  1  cropwatcher stations           both stations RECEIVED, not just stored
  2  cropwatcher geometry           re-measure; settle must then be < 2 cm
  3  cropwatcher check              confirm the settle
  4  cropwatcher proptest           motors spin, drone held down
  5  armed idle                     props turn, no lift
  6  20 cm hover, 10 s              the smallest real flight
  7  W alone                        must climb STRAIGHT — x, y unchanged
  8  forward alone, then release    must travel, stop, and HOLD
  9  Up+Down together               must hold the level exactly
  10 side steps, then a square      the whole law

Rungs 7-10 are what PR #26 changed. They are the test of it.

=========================================================================
OPEN QUESTIONS — carried between sessions until answered
=========================================================================

- Is a Flow deck fitted? Only deck.bcLighthouse4 is ever queried. A Flow deck
  v2 would add optical flow and a laser rangefinder, which would firm up the
  hold between Lighthouse updates. One param read settles it. NOT MEASURED —
  and not to be inferred from the kit photos, which was wrong for hours.

- Does the firmware's position controller track a setpoint ramping at
  0.20 m/s without feeling sluggish or overshooting on release? It is tuned
  for waypoints. This is the main unknown in PR #26 and only rungs 7-10
  answer it.

- drift_m and the commanded point are recorded in the flight trace and the
  agent log, but are NOT shown in the app. Whether that matters is a decision
  for after the first flight that uses them.
