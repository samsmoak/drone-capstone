CROPWATCHER ON LINUX — the 40 stages
====================================

The terminal install (`node scripts/install.mjs`) works on macOS (Apple silicon
and Intel) and Windows, and CI proves it — including a real sign-in — on all
three. Linux was never tried. What the code does today on Linux, read from it
(main at 476cfc8):

  - setup.mjs prints a link to Tauri's prerequisites and checks nothing.
  - install.mjs builds with --no-bundle and installs nothing (INSTALL is macOS
    or Windows only).
  - refuse-if-running.mjs returns "not running" on Linux without looking.
  - The Wi-Fi password store: keyring is built with the apple-native and
    windows-native features only. On Linux keyring 3.6.3 then uses its MOCK
    store (keyring/src/lib.rs:255-288) — the password "saves" and is gone at
    the next launch, silently.
  - The Crazyradio needs a udev rule on Linux or only root can open it; the
    agent would report "No drone answering".
  - CI has no Linux machine, so none of this has ever run.

Already right on Linux, read from the code: the agent's data folder
(paths.py, XDG), the shell's log path (lib.rs agent_data_dir), the Wi-Fi
network scan (a typed-name fallback), open-app.mjs, the CORS origin
(tauri://localhost), and cryptography (manylinux wheels carry their own
OpenSSL — the Intel-Mac failure cannot happen here).

PRIMARY SOURCES
  Tauri v2 prerequisites, Linux: https://v2.tauri.app/start/prerequisites/
  Bitcraze USB permissions:
    https://www.bitcraze.io/documentation/repository/crazyflie-lib-python/master/installation/usb_permissions/
  keyring 3.6.3 features: Cargo.toml [features], src/lib.rs (mock fallback)
  freedesktop Desktop Entry Specification 1.5; XDG Base Directory Specification

DECISIONS
  - Per-user install, no sudo: the program in ~/.local/lib/cropwatcher, a menu
    entry in ~/.local/share/applications, the icon in hicolor, a `cropwatcher`
    link in ~/.local/bin. Not an AppImage (needs FUSE 2, missing on current
    Ubuntu by default) and not a .deb (needs sudo). Same shape as the Windows
    per-user install.
  - Never run sudo from a script. The udev rule and the plugdev group need
    root; the installer detects whether they are in place and prints the exact
    commands. The agent names the problem when it meets it.
  - Keyring on Linux: Secret Service (sync-secret-service + crypto-rust). No
    OpenSSL link, persistent in GNOME Keyring / KWallet. Without a keyring
    daemon the save fails with a message — never a silent mock.
  - CI proves Linux with the same two steps as everywhere else: install.mjs,
    then check_sign_in.py. Nothing uploads.

NOT IN THIS PLAN
  - Linux installers to download (no downloads anywhere, by decision).
  - Linux ARM in CI (the containers used for iteration are arm64; CI is x86_64).
  - Real radio access on Linux — needs a dongle on a Linux machine.
