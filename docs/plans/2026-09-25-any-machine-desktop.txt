DESKTOP APP ON ANY MACHINE — the 50 stages
==========================================

The desktop app built and ran on the Apple-silicon MacBook it was developed on,
and nowhere else had been proven. On an Intel Mac, two things went wrong:

  - the sidecar check timed out (its 20 s startup limit was too short there),
    and
  - sign-in said "Could not reach the flight agent on this computer. Restart
    CropWatcher."

Neither is a credentials problem. The Supabase URL and publishable key are
already compiled into desktop/src-tauri/src/lib.rs. The error fires before any
request reaches Supabase: the window's fetch to the local agent threw.

WHAT THE DIAGNOSIS FOUND, from the code and CI:

  1. The sign-in form only renders once the agent has sent a session over the
     WebSocket, so the agent WAS up. It had stopped answering by the time the
     form was used.
  2. When the agent dies, the Rust shell emits the reason as `agent-log`
     events. Nothing in desktop/src listens for them, so the reason is thrown
     away and the operator is told to restart.
  3. Every release run since 2026-09-22 fails on windows-latest, lately with
     "'..' is not recognized": `pnpm sidecar` runs a bash script, and pnpm on
     Windows runs scripts through cmd.exe. (This first read "has never been
     built" — wrong; it built until 2026-09-21. See the end of this file.)
  4. On Windows, cflib opens the Crazyradio through libusb0 only
     (cflib/drivers/crazyradio.py, _find_devices), which needs the
     libusb-win32 driver installed once with Zadig. The site says "No driver to
     install", which is wrong on Windows.
  5. CI builds macOS for Apple silicon only; an Intel Mac cannot run the
     download. GitHub still offers `macos-15-intel` to public repositories.
  6. There is no one-command setup. A clone needs about six manual steps that
     differ per OS.

The actual cause on the Intel Mac is still unconfirmed. This plan makes the app
report it, rather than guessing a fix.

DECISIONS (locked with the user 2026-09-25)

  - No Docker: it cannot reach USB on macOS, and every user would have to
    install it.
  - No credentials beyond the publishable key. Flying still needs
    profiles.role = operator, enforced by RLS.
  - The agent stays a one-file PyInstaller binary.
  - One build path and one setup script, identical on macOS and Windows.
  - The Zadig driver step is explained by the agent, not automated.
  - Two PRs: PR 1 is "clone, build and run anywhere"; PR 2 is "download
    anywhere" (Intel CI and the download buttons).

ADDED WHILE PLANNING, and why:

  - The release workflow also runs on pull requests, with uploads disabled
    there. Otherwise the first proof that Windows builds would be a publish
    from main.
  - Its concurrency group becomes per-ref. A shared group with
    cancel-in-progress would let a PR build cancel a publish from main.

NOT IN THIS PLAN

  - Code signing (Apple Developer ID, Windows certificate).
  - Linux installers.
  - A universal macOS binary. PyInstaller's one-file output cannot be lipo'd,
    and a universal2 freeze needs every native wheel to be universal. Two
    installers, one per chip, instead.
  - Rewriting the live /setup page in the database. That is an owner action in
    /admin (see stage 45).

PHASE 1 — THE SIDECAR CHECK TOLERATES SLOW MACHINES             stages 4–10
─────────────────────────────────────────────────────────────────────────
  4  verify_sidecar.py: one STARTUP_TIMEOUT_S = 180 s for `--help` and for
     `serve`; CHECK_TIMEOUT_S = 240 s for `check`, which scans USB after
     starting.
  5  The wait fails fast. If the agent process exits while being waited on,
     report its exit code and its own output immediately, instead of "never
     opened port" after the full limit.
  6  The agent's output goes to a temporary file, not a pipe. A pipe nobody
     reads fills at 64 KB and stalls the process being timed.
  7  Refuse to start if the probe port (8791) is already taken. Otherwise a
     survivor of an earlier run answers and the check passes against the wrong
     binary.
  8  Stop the agent the way the app does: start it with --exit-with-parent,
     close its stdin, and require the port to be released. This proves the
     no-orphan invariant on every OS CI builds; it had only been measured on
     macOS.
  9  If closing stdin does not stop it, kill the whole process tree
     (taskkill /T on Windows, SIGKILL to the process group elsewhere) and FAIL.
     An agent that outlives its window keeps the radio.
 10  Print how long the agent took to answer, so the next "too slow" report
     comes with a number.


PHASE 2 — ONE BUILD PATH FOR EVERY OS                          stages 11–18
─────────────────────────────────────────────────────────────────────────
 11  backend/agent/packaging/build_sidecar.py replaces build_sidecar.sh:
     PyInstaller, copy to desktop/src-tauri/bin/cropwatcher-agent-<triple>,
     then verify. Standard library only.
 12  Read the triple from rustc. Fall back to ~/.cargo/bin/rustc when rustc is
     not on PATH (a login shell often lacks it).
 13  Refuse a Python whose CPU differs from Rust's target: an x86_64 Python
     under Rosetta on an Apple-silicon Mac would produce an Intel agent named
     for arm64, which is exactly the invisible mismatch the triple exists to
     prevent.
 14  Refuse to run without PyInstaller in the running interpreter, and name the
     command that installs it.
 15  pyproject.toml: a `packaging` extra (pyinstaller>=6.10), so setup and CI
     install the same thing.
 16  desktop/scripts/sidecar.mjs: finds the agent venv's Python (bin/ or
     Scripts/python.exe) and runs build_sidecar.py. `pnpm sidecar` calls it,
     and so does beforeBuildCommand, through build:all.
 17  desktop/scripts/open-app.mjs: `pnpm app` opens the built app on macOS,
     Windows and Linux; it was macOS `open` only.
 18  Delete build_sidecar.sh, and repoint every reference: the spec,
     verify_sidecar, ./cropwatcher, desktop/README.md, the workflow and the
     site.


PHASE 3 — ONE SETUP COMMAND                                    stages 19–27

 19  scripts/setup.mjs at the repo root, run as `node scripts/setup.mjs`. Node

 20  Check Node against Vite's own floor (^20.19 || >=22.12).
 21  Find Python 3.11 or newer: CROPWATCHER_PYTHON, then python3.11–3.13, then

 22  Check Rust (rustc, reading the host triple) and that Python's CPU matches

 23  Check the native toolchain: xcode-select -p on macOS; vswhere and the
     "Desktop development with C++" tools on Windows.
 24  Check pnpm 10.
 25  Create backend/agent/.venv. An existing venv that cannot run, is older
     than 3.11, or is built for a different CPU (for example one copied from
     another Mac) is recreated, and the script says why.
 26  Install the agent with the packaging extra (plus dev with --dev), then run
     `pnpm install --frozen-lockfile` in desktop/.
 27  Finish with the next command (`cd desktop && pnpm app`) and, on Windows,

PHASE 4 — THE AGENT EXPLAINS ITSELF                            stages 28–33
─────────────────────────────────────────────────────────────────────────
 28  LocalCORS logs each refused preflight: origin, method and path, once per
     origin, so a page cannot flood the log. A refusal no log records is
     invisible (OWASP A09).
 29  flight/link.py: _radio_seen() looks for the dongle through the bundled
     libusb-1.0, which on Windows lists devices whatever their driver.
 30  _windows_driver_problem(): on Windows, no libusb0 backend means "driver
     not installed". A backend that cannot see a dongle libusb-1.0 sees means
     "wrong driver". Each gets its own Zadig instruction.
 31  _nothing_found_reason() puts the driver problem ahead of "switch it on".
     Other operating systems keep the current wording.
 32  flight/core.py: `cropwatcher check` gives the same reason after "no drone
     found", which verify_sidecar still matches on.
 33  Tests for every branch: driver missing, wrong driver, driver fine, not
     Windows, dongle absent, USB unreadable. Plus the CORS log line, logged
     once.


PHASE 5 — THE WINDOW SAYS WHY                                  stages 34–40
─────────────────────────────────────────────────────────────────────────
 34  lib.rs: remember the agent's last error-looking line (ERROR, CRITICAL, a
     PyInstaller [PYI-…:ERROR], or a Python "…Error:" line).
 35  lib.rs: on exit, compose one sentence: the exit code plus that line. A bind
     failure ("address already in use", WSA 10048) becomes "port 8765 is
     taken — another copy is running".
 36  lib.rs: keep that sentence in state and emit `agent-exit`. Add the
     `agent_exit` command, because an exit before the window's listener exists
     would otherwise be lost. That includes a failure to spawn at all.
 37  lib.rs: an `agent_log_path` command, mirroring paths.py (the data dir,
     honouring CROPWATCHER_DATA_DIR), so the window can say where the log is.
 38  agent.ts: when a command's fetch throws, ask /health (no-cors, 2 s) whether
     anything is listening. If not: "not running", with the exit reason. If so:
     "running, but this request did not reach it", naming the request. The
     blanket "Restart CropWatcher" goes.
 39  App.tsx: listen for `agent-exit` (listener first, then ask once), and add
     the reason and the log path to the existing "Not connected" message. Text
     only; no layout change.
 40  Rust unit tests for the sentence: bind failure on macOS and Windows,
     traceback, no error line, signal.

WHAT CHANGED DURING IMPLEMENTATION (2026-09-25) — recorded, not rewritten
─────────────────────────────────────────────────────────────────────────
PHASE 8 (PR 2: the Intel .dmg and download buttons) WAS DROPPED. While building
it, the page showed a Windows installer from 2026-09-21, which disproved this
plan's claim that no Windows installer had ever been built. It had: Windows
broke on 2026-09-22, first because the installer (65.3 MB, after numpy and
scipy joined the agent) exceeded Supabase's 50 MB upload limit, then because
of the bash script. Asked where installers should go, the owner answered that
nothing is uploaded — people install from a terminal. So instead:

  - scripts/install.mjs: setup, build (only the bundle this OS installs from),
    install (Applications / per-user on Windows), refusing to replace a
    running copy. One command after a clone.
  - The release workflow became desktop-install.yml: install.mjs on
    macos-latest, macos-15-intel and windows-latest; no uploads, no secrets.
  - The setup guide's build steps became "Install from a terminal".
  - verify_sidecar recognised only "no drone found", so every radio-less
    build had reported "a radio answered". It now recognises every reason
    radio.py gives, with a test tying the two together.

Stage 48's minimum-macOS measurement found that a locally built app bundles
the build machine's libraries (macOS 26.0 minimum on this Mac). Harmless now
that every machine builds for itself; recorded in releases.txt.

LEFT FOR THE OWNER: the website's download step and /apps still offer the
stale bucket files; the unused SUPABASE_* GitHub secrets should be deleted;
/admin → Reset to original for the Setup page.
