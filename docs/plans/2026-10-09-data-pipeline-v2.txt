THE WORDS, USED THE SAME WAY EVERYWHERE

  Reading        one 10 Hz telemetry row of a flight (the flight CSV).
  Sample         one 1 Hz row of a session (samples.csv, session_samples).
  Flag           the cleaner's mark on one value (or a whole row): it is not
                 used downstream. A flag never edits the value.
  Clean series   the raw series with the flagged values left out.
  Expected       what the signal would read with nothing unusual around the
                 drone: the cooling curve for temperature, the height-corrected
                 trend for pressure.
  Residual       reading − expected.
  Block          a stretch of readings whose residual holds one level
                 (a PELT segment).
  Event          a block the classifier says departs from expected (a
                 statistical claim, in noise units).
  Finding        an event the interpreter has judged, with a severity, a
                 sentence, where and when, and the frames taken then.
  Notification   one finding (warning or critical) for one operator, kept in
                 the database until that operator reads it.

WHAT THE LAPTOP'S OWN FLIGHTS SHOWED (measured 2026-10-09, before planning)

  1. hampel@1 on 66 real flights (≥ 287 rows), faults planted by
     ml/sensor-faults/plant_faults.py, seed 0:
       caught 3 541 / 3 564 (99.4 %) · false flags 332 / 223 623 (0.148 %)
       — 292 of them corrected_temp "spikes" · 139 flags INSIDE the planted
       hand-warmer ramps (the rule is 0).
     → the bar the new cleaner must clear, on the same corpus.
  2. In a normal mission flight raw_temp COOLS steadily in the propeller
     airflow (48b1eb79: 34.7 → 29.6 °C in 48 s), and corrected_temp is
     raw_temp minus a constant offset (12.67), so it falls 6 °C too.
     ambient_est stays at the operator's typed 22.00 °C.
     → a "compare to the flight median" detector would flag every normal
       flight. Temperature is judged against a fitted COOLING CURVE, on
       raw_temp (the sensor itself), not corrected_temp (which also steps
       when thermal_state switches).
  3. Pressure vs height on four missions: −0.16 to −0.36 hPa/m, steeper than
     hydrostatic −0.12 (the drone's own downwash near the floor). Residual
     noise after a height fit: 0.024–0.033 hPa (MAD, scaled).
     → pressure is height-corrected with PHYSICS (ρ·g·h, ρ from the row's
       air_density_kg_m3), never a per-flight fit (a fit would absorb a real
       event that happened at one height). Pressure findings carry a higher
       minimum and say "pressure" plainly; the downwash residue is a known
       limit, written down.
  4. z_m in the flight CSV is height above the takeoff floor (telemetry/
     row.py) — the height the correction needs, already per row.


DECISIONS (calls that could have gone the other way)

  D1  THE UNIT OF WORK BECOMES THE FLIGHT. The cleaner, enhancer and
      classifier run ONCE over the whole flight; inspection points become a
      view (readings and frames carry point_id). Blocks span points and
      transit ("came to a new place"), which a per-point stage cannot see.
      The v1 decision "the same stage code serves batch and live per point"
      is replaced: live (story 4.9) will run the same stages over the flight
      so far. Contract v2, PIPELINE_VERSION "2".
  D2  THE CLEANER IS REPLACED, NOT EXTENDED (owner, 2026-10-09). robust@1
      replaces hampel@1 outright — one implementation. It must beat hampel@1
      on the corpus in (1) or it does not ship.
  D3  CLASSIFICATION = BLOCKS AGAINST EXPECTED. Expected: a robust
      first-order cooling fit for temperature; a robust linear trend of
      height-corrected pressure. Blocks: PELT (Killick et al. 2012) on the
      residual, written in numpy (no new runtime dependency), checked against
      `ruptures` in tests (dev dependency only). No ML model for sensors: no
      labelled runs exist.
  D4  NO IMAGE MODEL. No labelled photos exist (story 4.1). Every frame's
      label is "unknown — no image model yet", unless its quality makes it
      unusable ("too dark", "blurred"). A finding's image support is
      "cannot tell" — said, never guessed. Telemetry is the source of truth.
  D5  ENHANCEMENT = CLAHE (OpenCV, opencv-python-headless) + a frame-quality
      measure (variance of the Laplacian, mean brightness, clipped share).
      Contrast is the frames' problem, not resolution, and CLAHE invents no
      detail. Kevin's evaluation (origin/feat/dpp-enhance) can still swap in
      an upscaler later behind the same contract.
  D6  THRESHOLDS ARE NOISE-RELATIVE + A PROVISIONAL PHYSICAL MINIMUM. An
      event needs a block mean ≥ Z_EVENT × the flight's own noise (σ from
      the residual's first differences). A finding is a warning only when
      it also clears a physical minimum (°C, hPa) — PROVISIONAL, calibrated
      on the corpus (no normal flight may raise a warning) and on planted
      hand-warmer ramps (every one must), until the lab's hand-warmer runs
      measure them. Every number cites ml/anomaly-eval/MEASUREMENTS.txt.
  D7  WORDS FROM TEMPLATES, NUMBERS EXACT. Interpret fills fixed sentences
      from the event's numbers. No LLM.
  D8  RESULTS LIVE ON THE LAPTOP FIRST (result.json), then upload through the
      outbox (CLAUDE.md invariant 6). Two tables: pipeline_results (one row
      per flight, the whole result as jsonb) and pipeline_findings (one row
      per finding, for queries and notifications). Finding ids are
      deterministic (uuid5 of flight, signal, start, end), so re-processing
      upserts instead of duplicating, and stale findings are deleted.
  D9  OWNERS ARE DENORMALISED BY A DATABASE TRIGGER, not by opening profiles.
      sessions and flights get operator_email and operator_name, filled
      server-side from profiles (never from what a client sends) and
      backfilled for existing rows. Profiles stay "read own" — no operator
      can list every account's email. Owners are shown, not used to hide
      anything: every signed-in user still sees every flight.
  D10 NOTIFICATIONS ARE ROWS. A trigger on pipeline_findings inserts one
      notifications row per operator for each warning or critical finding
      (unique per user and finding, so a re-upload never re-notifies).
      Read-own, mark-own-read (column grant on read_at only), no client
      insert. Realtime makes them arrive instantly; the table makes them
      persist. Desktop: an OS notification when a processed flight has a
      warning or worse (tauri-plugin-notification).
  D11 SESSION = SUPERSET OF ITS FLIGHTS. The session page shows the 1 Hz
      vitals for the whole session AND every flight's 10 Hz telemetry on one
      session clock, all frames (original and enhanced), every finding, and
      the raw rows of every flight. The flight page shows the same sections
      for its own slice (shared components).
  D12 THE GREENHOUSE "Zone health" SECTION IS REMOVED from both pages. The
      predictions table stays (nothing is dropped from the database).

PHASE 4 — CLASSIFY: BLOCKS (dpp/classify)                           45–60

  45  The airborne window: thermal_state FLIGHT…, skipping the first
      SETTLE_S after takeoff (the correction engine's step, row 27 of the
      fixture) — SETTLE_S measured on the corpus.
  46  Temperature: raw_temp in °C (the flight's unit converted here — an
      absolute × 9/5 + 32, a difference × 9/5 only). Expected: T∞ + A·e^(−t/τ),
      τ on a log grid, (T∞, A) by least squares per τ, iterated with Huber
      weights (robust to a real event). Too few points → a robust line.
  47  Pressure: station_pressure_hpa + ρ·g·z_m / 100 (ρ from the row, g =
      9.80665); rows whose height is untrusted are left out. Expected: a
      robust line (the room's drift).
  48  Noise σ per signal: 1.4826 × MAD of the residual's first differences
      / √2 — blind to blocks, which a plain MAD is not.
  49  PELT in numpy (cumulative sums, L2 cost on the residual), penalty
      PEN × σ² × ln n, minimum block MIN_BLOCK readings; run per stretch of
      usable readings (never across a gap or a flag).
  50  Cross-check against ruptures (dev dependency) on random series:
      identical breakpoints.
  51  Events: blocks with |mean residual| ≥ Z_EVENT × σ, with direction,
      delta, z, slope, the point ids they overlap, mean position (only when
      measured).
  52  Tracks: expected per reading index (for the web's "expected" line).
  53  Images: per frame, "unknown — no image model yet", or "unknown —
      too dark / blurred" from the frame's quality. sensors: faulty if any
      event, normal if both models fitted and no event, unknown with the
      reason otherwise. Features named with units.
  54  ml/anomaly-eval/: evaluate.py over the corpus — false events per
      normal flight — and over planted events: a hand-warmer ramp (+5 °C in
      10 s, held), a cooling draught (−3 °C), a pressure step (+0.5 hPa,
      5 s): detection rate, start-time error, false events.
  55  Choose SETTLE_S, PEN, MIN_BLOCK, Z_EVENT by those numbers; write them
      in ml/anomaly-eval/MEASUREMENTS.txt with the table.
  56  Tests: synthetic cooling curve (no event), cooling + ramp (one rise
      event at the right place), pressure step at constant and changing
      height (event only for the real step), flagged values never reach a
      model (plant a flagged spike: identical output), °F = °C, empty and
      too-short flights give unknown with a reason, deterministic.
  57  Under 1 s for a 3-minute flight on this laptop, measured.
  58  dpp-classify ticket rewritten: the sensor half built (no ML); the

RISKS, AND WHAT IS DONE ABOUT EACH

  - A "better" cleaner that is only better on paper → the corpus scores,
    both cleaners, same seeds, in MEASUREMENTS.txt; it ships only if better.
  - The cooling fit absorbing a real event → Huber weights; a planted ramp
    must still be found (acceptance).
  - Pressure downwash near the floor → physics correction only; a higher
    pressure minimum; the limit written in classify.txt.
  - OpenCV in the frozen agent → cv2 in SELFTEST_MODULES; the freeze and
    verify run once before dpp/enhance merges.
  - A migration that works locally but not live (platform defaults) →
    explicit grants in every migration (20260916000004's rule).
  - Re-notification on re-processing → unique (user, finding) + insert-only
    trigger + deterministic ids.
  - Branch conflicts between stacked branches → one owner of each file per
    branch; integration merges in the publish order above.
