THE JOB, IN ONE PARAGRAPH

Given one inspection point's readings, return a flag for every value that
comes from a MISBEHAVING SENSOR: missing, physically impossible, a one-sample
spike, stuck at one value, or a gap in time. FLAG, NEVER EDIT, NEVER DELETE.
The next stages skip flagged values, which is what the story means by
"removed".


THE TRAP THIS STAGE EXISTS TO AVOID

The drone is inspecting for REAL HEAT. The acceptance test for the whole
project is a box heated with a hand warmer (story 4.6). A real heat event is a
sustained, physically plausible rise, and IT MUST PASS THROUGH CLEANING
UNTOUCHED. If your cleaner flags it as a spike, the pipeline erases exactly
the thing it was built to find.

So the line you draw is:

  Sensor fault → flag it                 Real event → leave it
  ──────────────────────────────────────────────────────────────────────────────
  One sample far off its neighbours,     A rise held for seconds
  then straight back
  A change faster than the sensor or     A change at a plausible rate
  air can physically move
  The exact same value for longer than   A slow drift
  the noise floor allows
  None/NaN, or outside the sensor's      Any in-range, continuous signal
  physical range

Your tests must prove both halves (see ACCEPTANCE).


INPUTS AND OUTPUTS

Exactly as ../done/dpp-contract.txt, "Stage 1":

  class YourCleaner:
      name = "hampel"            # your choice, short
      version = "1"              # bump whenever flags could change
      def clean(self, data: PointData, ctx: FlightContext) -> CleanResult: ...

- CleanResult.readings is THE INPUT TUPLE, UNCHANGED.
- One ReadingFlag per bad value, with `column` set. For a gap, one flag with
  column=None on the FIRST READING AFTER THE GAP.
- `reason` is a sentence an inspector reads, with the numbers in it. For
  example: "corrected_temp 61.3 °F is 9.8 °F off the 1.1 s median (limit
  2.4 °F): a one-sample spike."


COLUMNS IN SCOPE

  Priority  Columns                            Why
  ──────────────────────────────────────────────────────────────────────────────
  Must      corrected_temp, raw_temp,          the measurements the inspection
            station_pressure_hpa               is about
  Should    x_m, y_m, z_m, battery_v           position tags every reading; the
                                               battery explains a sagging
                                               sensor
  Out       thrust, motor_m1..4, roll_deg,     control values, not measurements
            etc.

Temperatures arrive in ctx.temp_unit ("C" or "F"). A threshold written in °C
must be converted before comparing. A TEST MUST COVER A FAHRENHEIT FLIGHT.


SUGGESTED METHODS (you choose; justify with measurements)

  missing       Value is None or NaN. Trivial, but do it first.

  out_of_range  Outside the sensor's physical range. Take the range from the
                DATASHEET OF THE PART ON THE DRONE, and cite it in a comment.
                Don't guess.

  spike         HAMPEL FILTER: rolling median over a window, flag where
                |x − median| > k × 1.4826 × MAD. Start around 11 samples
                (1.1 s at 10 Hz) and k = 3. The MAD is 0 on a flat signal, so
                put a floor under it (the measured noise floor), or every tiny
                wiggle is a spike.

  stuck         The same value for more than N consecutive samples. Only
                meaningful if the signal is normally noisy. MEASURE FIRST: the
                correction engine may produce smooth values, and a smooth
                signal is not a stuck one.

  gap           Time between consecutive recorded_at > 2.5 × the expected
                period. Telemetry is 10 Hz, so the expected period is 0.1 s.
                Measure the real jitter first.

All of this is plain numpy. No machine learning is needed, and none is
wanted: a rule you can explain beats a model you can't, for this stage.
(scikit-learn's IsolationForest is the known next step, IF rules provably miss
something. It is not in the runtime dependency list, so it would be trained in
ml/ and exported to ONNX.)

ACCEPTANCE — what "done" means

The PDF's criterion, made measurable. Adjust the numbers with Samuel if the
data argues otherwise.

  [ ] EVERY PLANTED FAULT IS FLAGGED, with the right `kind` and `column`
      (100 % of planted faults, over at least 3 real flights).
  [ ] CLEAN ROWS STAY CLEAN: at most 1 % of unplanted values flagged. Report
      the exact rate.
  [ ] THE HAND-WARMER RAMP GETS ZERO FLAGS.
  [ ] A Fahrenheit flight and a Celsius flight give the same flags for the
      same physical signal.
  [ ] Every conformance check passes (tests/pipeline/conformance.py).
  [ ] An empty point (no readings) returns an empty result, not an error.
  [ ] Every threshold cites ml/sensor-faults/MEASUREMENTS.txt.
  [ ] Time per point measured and reported.
  [ ] Gates pass: ruff check . && mypy cropwatcher && pytest
