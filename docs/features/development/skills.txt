DEVELOPMENT SKILLS — /feature, /copy-adapt, /preflight and /adapt
==================================================================
Last verified: 2026-09-27 against chore/project-skills-and-feature-docs — the
kit's 11 tests pass from .claude/feature-kit/; the SessionStart hook installs

WHAT IT IS

Claude Code slash commands that shape how work on this repository is planned
and built. They are committed with the project, so anyone who opens the repo in
Claude Code — including a Claude Code cloud session — can run them; they no
longer depend on one person's machine.

/feature and /copy-adapt are the current versions: byte-for-byte copies of the
owner's global ~/.claude/commands/ files, added 2026-09-27. /preflight and
/adapt are their older, shorter predecessors and are kept as they were.


WHERE IT LIVES

  .claude/commands/feature.md      /feature <task>      (current)
  .claude/commands/copy-adapt.md   /copy-adapt <task>   (current)
  .claude/commands/preflight.md    /preflight <task>    (older)
  .claude/commands/adapt.md        /adapt <task>        (older)
  .claude/feature-kit/             kit.py + graph_check.py + templates + tests,
                                   the tool /feature and /copy-adapt run first
  .claude/settings.json            SessionStart hook: copies the kit to
                                   ~/.claude/feature-kit/ when that is absent
  docs/PROJECT_PROFILE.txt         what the kit generated, then settled by hand
  docs/graph.config.json, docs/graph_check.py, docs/GRAPH_STATE.txt

Claude Code loads commands from `.claude/commands/` in the project automatically.
A copy in ~/.claude/commands with the same name is the personal version; the
project copy is the shared one. Edit the project copy and commit it.


/preflight — the general execution checklist

  1. Orient in THIS repo: read CLAUDE.md and docs/README.md, pin versions from
     the lockfiles, name the invariants that apply.
  2. Apply the standards: reuse before writing, tokens only, WCAG 2.2 AA
     measured not eyeballed, four async states, server-side authorization,
     typed errors, no secrets in logs.
  3. Pre-flight ritual per point of the request — current state (verified),
     agreement, objection, industry standard, recommendation — then a short
     lock-in list of decisions, and WAIT for "go".
  4. On go: implement, run every gate, report pass/fail honestly.
  5. Update docs/features/* with what actually shipped.
  6. Ship only on explicit approval (standing approval for this repo: commit,
     push and merge after every build — see CLAUDE.md "Git"). Nothing is
     published on merge: every machine builds the app from main with
     `node scripts/install.mjs`, and CI only proves it builds (releases.txt).


/adapt — copy, then adapt only what the target forces

  - Find the most-hardened source; say which and why.
  - Decide: DOMAIN port (same stack, new subject) or PLATFORM port (same
    subject, new stack). They adapt along opposite axes.
  - Copy structure, visuals and code shape faithfully; change only routes,
    models, vocabulary, business rules and data source.
  - Port the whole feature: UI, state, data access and the server side.
  - Residue sweep: no leftover names, copy, routes or comments from the source.
  - Report the adaptation delta, citing the source file for each piece.


HOW THEY WERE USED HERE

  - docs/features/frontend/portfolio.txt is a /adapt domain port of
    ../doctor-portfolio: its "What changed in the port" table is the delta.
  - The desktop UI primitives (desktop/src/ui.tsx) were copy-adapted from
    web/components/ui/states.tsx, a platform port.
  - docs/plans/ keeps the plan written before a large /preflight run, as a
    record of what was decided and in what order.


INVARIANTS

- The skills call `python3 ~/.claude/feature-kit/kit.py` — a HOME path, which
  a cloud session does not have. The SessionStart hook fills it from the
  committed copy; that is why the skill files stay byte-identical to the
  global ones instead of being edited to a repo path. On the owner's Mac the
  folder exists, so the hook does nothing.
- Two copies drift. When the global /feature, /copy-adapt or the kit changes,
  copy it here again (and `kit.py upgrade` for docs/graph_check.py) — inside
  this repo the project copy wins over the global one.
- A skill in ~/.claude/commands is invisible to everyone else. If the project
  depends on it, it belongs in .claude/commands/ and in git.
- The skills discover project rules from the repo; they never carry another
  project's conventions. Keep project facts in CLAUDE.md and docs/, not in the
  skill files.
