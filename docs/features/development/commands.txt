1. WHAT IT IS
--------------------------------------------------------------------------------
"What do I type, and from where?" Every block below leads with the directory to
be in (and, for the agent, activating its venv), then the commands you run from
there with a one-line note on each. If a command here disagrees with the code,
the source files in WHERE IT LIVES win.

2. WHERE IT LIVES
--------------------------------------------------------------------------------

AGENT CLI — the `dronedeck` command (motors only where noted)
  cd backend/agent && source .venv/bin/activate
  (Windows PowerShell: .venv\Scripts\Activate.ps1)

  dronedeck check                 Run every gate; never spins a motor. The
                                    "is this machine OK to fly" check.
  dronedeck setup                 Install the drone's software — the only way:
                                    the app has no install button or route.
                                    QUIT DroneDeck first (it holds the radio).
                                    --check (read only), --reinstall
                                    main|lighthouse|camera,wifi. Installed app:
                                    …/DroneDeck.app/Contents/MacOS/
                                    dronedeck-agent setup — Set up step 2 shows
                                    this machine's exact line to copy.
  dronedeck selftest              Load every library the agent only loads on
                                    demand — catches a broken bundled dependency.
  dronedeck serve                 Run the local API on 127.0.0.1:8765 that the
                                    desktop app talks to. --host, --port, and
                                    --exit-with-parent (land, cut motors and exit
                                    when stdin closes, so quitting the app cannot
                                    strand an agent holding the radio).
  dronedeck stations              Watch which Lighthouse base stations the
                                    drone sees, live. --seconds N to auto-stop.
  dronedeck geometry              Measure where the base stations are; no
                                    motors. --quick (one sample, restore hold
                                    now), --distance, --countdown, --dry-run.
  dronedeck proptest              The firmware's propeller test. MOTORS SPIN.
  dronedeck hover                 Take off, hold a steady height, land. MOTORS
                                    SPIN. --height (m), --secs, --ambient (e.g.
                                    74F or 22C — the unit every temperature in
                                    the flight is stored in), --fence, --no-log.
  dronedeck mission --id ID       Check, then fly, a mission saved on this
                                    laptop (built in the app). MOTORS SPIN.
                                    --dry-run checks and describes it, no connect.
  dronedeck process --flight ID   Run the data pipeline over a recorded flight;
                                    never connects. Also: --session ID (on-ground
                                    samples), --all (everything unprocessed),
                                    --fixture (the test fixture, source checkout
                                    only), --live-point POINT (with --flight).
  dronedeck mission-report --flight ID
                                    Per inspection point: leg, transit, settle,
                                    hold, drift, flown-vs-estimate, and suggested
                                    controller constants. Reads files, no radio.
                                    Repeat --flight to combine flights; --json.
  dronedeck calibrate --flight ID --at POINT
                                    Measure what a KNOWN heat source did (the
                                    hand-warmer flights) and recommend anomaly
                                    thresholds. One --at per --flight, same order.

  Global: -v / --verbose on any command; --uri sets the radio URI on connecting ones.

AGENT GATES — the definition of done for flight code
  cd backend/agent && source .venv/bin/activate

  ruff check .                      Lint.
  mypy dronedeck                  Type check.
  pytest                            The tests; guards and checks need no drone.
  pytest -k guard                   Just the in-flight guards.
  pytest tests/mission/test_mission_sim.py
                                    The mission simulator (no radio) — the
                                    "built in simulation" proof CI runs.
  pytest -m hardware                The real-drone tests. DESELECTED (skipped)
                                    without a radio and drone plugged in.

WEB — the Next.js dashboard and public site
  cd web

  pnpm dev                          Run the dev server.
  pnpm build                        Production build (a gate).
  pnpm start                        Serve a production build.
  pnpm lint                         ESLint (a gate).
  pnpm typecheck                    next typegen, then tsc --noEmit (a gate).
                                    typegen MUST run first — a bare tsc fails on a
                                    fresh clone (PageProps route types exist only
                                    after it).

DESKTOP — the Tauri app (manual control, bundles the agent)
  cd desktop

  pnpm dev                          Vite dev server (the web view only).
  pnpm build                        tsc, then vite build (the gate).
  pnpm sidecar                      Freeze + verify the agent into the bundled
                                    sidecar the app ships (build_sidecar.py).
  pnpm build:all                    Refuse if running, then sidecar + build.
  pnpm app                          Freeze the agent, build the installer, open
                                    it (pnpm tauri build + open-app.mjs).
  pnpm preview                      Preview a built web view.
  pnpm test                        The keyboard-mapping tests (keys.test.mjs).

  cd desktop/src-tauri
  cargo test                        The Rust shell's own tests (a gate).

SCRIPTS — install and machine setup (any OS: macOS, Windows, Linux)
  cd <repo root>

  node scripts/install.mjs          How everyone installs the desktop app:
                                    setup, build, install. --open, --no-install
                                    (build only), --dev (also the agent's test
                                    tools).
  node scripts/setup.mjs            Set up a machine: checks Python 3.11+, Rust,
                                    pnpm, native toolchain; creates the agent
                                    venv. --check (check only, change nothing),
                                    --dev (also test + lint tools).

SUPABASE — migrations, schema, generated types (cloud + local stack)
  cd backend
  (The Supabase CLI resolves supabase/ relative to the working directory, so it
  is run from backend/, not the repo root — see CLAUDE.md "Layout".)

  supabase start                    Start the local Supabase stack (Docker).
  supabase db reset                 Drop everything and re-apply migrations +
                                    seed. LOCAL ONLY — destructive.
  supabase db push                  Apply migrations forward to the linked cloud
                                    project. Safe; creates nothing destructive.
  supabase link --project-ref <ref> Link this repo to a hosted project.
  supabase gen types typescript --linked > ../web/types/database.ts
                                    Regenerate web/types/database.ts from the
                                    linked schema (run from backend/, so the
                                    relative path points up into web/).
  supabase login                    Account-level browser login — needed once
                                    before linking a cloud project.
  ./scripts/setup-supabase.sh <project-ref>
                                    (from repo root) Link this repo to a hosted
                                    project, apply the schema (db push), and
                                    print the env vars Vercel needs. Needs
                                    `supabase login` first.

RLS / DATABASE CHECKS — prove the policies against a running database
  cd <repo root>
  (Each creates and deletes its own rows, so it is safe against hosted. They need
  connection env vars — SUPABASE_API, SUPABASE_ANON, SUPABASE_SERVICE,
  CHECK_EMAIL, CHECK_PASSWORD; see supabase/rls-and-grants.txt for each one.)

  python backend/supabase/checks/rls_check.py             Row-level security —
                                                          what each role may and
                                                          may not do (15/15).
  python backend/supabase/checks/owner_check.py           Owners see only theirs.
  python backend/supabase/checks/results_check.py         Results land + read back.
  python backend/supabase/checks/session_results_check.py A session's own result.
  python backend/supabase/checks/playback_check.py        flight_plans + playback.
  python backend/supabase/checks/notifications_check.py   Notifications: one each.

FIRMWARE — the Crazyflie app (drone_wifi) on the drone's STM32
  cd firmware/drone-wifi

  ./build.sh                        Run the wire test, then build the stock
                                    release + the app into build/cf2.bin. It
                                    checks .config rather than trusting it — a
                                    silently-dropped app option flashes but never
                                    runs, so build.sh refuses that build.

  cd backend/agent && source .venv/bin/activate
  python -m dronedeck.flash_firmware ../../firmware/drone-wifi/build/cf2.bin
                                    Flash the built image to the STM32 by radio
                                    (once per drone, and after any firmware
                                    change). The bootloader is untouched — an
                                    interrupted flash recovers by holding power
                                    ~3 s and flashing again.

DATA ON THIS MACHINE — getting at recorded flights and results (recipes, macOS)
  (Plain shell, not dronedeck subcommands. Paths come from paths.py; Windows
  is %APPDATA%\DroneDeck, Linux $XDG_DATA_HOME/DroneDeck; DRONEDECK_DATA_DIR
  overrides it.)

  open ~/Library/Application\ Support/DroneDeck
                                    Open the data folder in Finder: flights/,
                                    results/, missions/, rooms/, outbox/, logs/.
  find ~/Library/Application\ Support/DroneDeck/flights -name 'flight_*.csv' \
    | sed -E 's|.*/flight_([0-9a-f]+)_.*|\1|' | sort -u
                                    List recorded flight IDs (the hex in each
                                    filename) — what --flight / mission-report want.
  open ~/Library/Application\ Support/DroneDeck/logs/agent.log
                                    The agent log — where a sidecar crash leaves
                                    its reason behind.

HARDWARE / LAB PASS — ONLY with the radio plugged in and a charged battery
  cd backend/agent && source .venv/bin/activate

  dronedeck check                                       Pre-flight gates.
  dronedeck hover --height 0.3 --secs 30 --ambient 74F  A real 30 s hover.
  pytest -m hardware                                      The real-drone tests.
  Report pass / fail / SKIPPED honestly. A cloud session has no radio, so these
  are skipped there and must be reported as skipped — never claimed done.

3. DECISIONS
--------------------------------------------------------------------------------
• A FLAT INDEX, NOT A SECOND SETUP GUIDE. The agent's from-source setup, venv
  creation and driver troubleshooting live in ../backend/running-from-source.txt
  and are not repeated here — this doc points there. Duplicating them is how two
  setup guides drift apart.
• RECORDED FLIGHTS GO TO THE APP DATA DIR, not a relative organized_flights/.
  CLAUDE.md's "Commands" still shows `# writes organized_flights/` beside hover;
  that comment is stale — the real location is the per-user data dir (macOS
  ~/Library/Application Support/DroneDeck/flights, see paths.py).
• SLASH COMMANDS ARE NOT SHELL COMMANDS. /feature and friends are Claude Code
  skills in .claude/commands/ (development/skills.txt), deliberately out of this
  index so it stays a reference of things you type in a terminal.

--------------------------------------------------------------------------------
4. INVARIANTS
--------------------------------------------------------------------------------
• Any command that spins a motor (proptest, hover, mission) needs a clear space,
  a charged battery (the supervisor refuses below ~3.75 V), and the radio. The
  rest (check, process, mission-report, calibrate, the gates) never touch it.
• pytest -m hardware is deselected without a drone — a green run with no drone
  means those tests did not run, not that they passed.
• The Supabase CLI runs from backend/ (it resolves supabase/ by the working
  directory); `db reset` is local-only and destructive, `db push` is the forward,
  non-destructive apply to the cloud project.
