RELEASES — how a commit becomes an installed app
================================================

WHAT IT IS

CropWatcher is installed from a terminal, not downloaded. On any Mac (Apple
silicon or Intel), Windows PC or Linux PC:

  git clone https://github.com/samsmoak/drone-capstone.git
  cd drone-capstone
  node scripts/install.mjs

That checks the toolchain, installs the agent and the app's packages, freezes
and verifies the agent, builds the app and installs it — into Applications on
a Mac, for the current user on Windows and Linux. Running it again after `git pull`
updates it in place.

CI runs exactly that command on an Apple-silicon Mac, an Intel Mac, a
Windows PC and a Linux PC (ubuntu-latest), on every pull request and every push to main that can change the
app. Nothing is uploaded.

The rule this exists for: **what people install must never be behind the code
on main, and must work on the machine they have.** Every machine builds its
own, from main, so the first half holds by construction; CI proves the second.


WHERE IT LIVES

  scripts/install.mjs                     the one command: setup, build, install
  scripts/setup.mjs                       the toolchain checks and dependencies
  desktop/scripts/sidecar.mjs             `pnpm sidecar` → build_sidecar.py
  backend/agent/packaging/build_sidecar.py  freezes and verifies the agent
  .github/workflows/desktop-install.yml   runs install.mjs on the three machines
  web/lib/site-content.ts                 the setup guide's terminal steps


WHEN CI RUNS

  push to main or a pull request touching desktop/**, backend/agent/**,
    scripts/** or the workflow itself
  "Run workflow" by hand

The path filter is deliberate: a docs or web change cannot affect the install,
and three runners are not free. Add to the list when something new can affect
the app; do not remove the filter.


DECISIONS

- NO DOWNLOADS (user, 2026-09-25). Until then CI published a .dmg and an .exe
  to a public Supabase bucket, read by /apps. It stopped working without
  anyone noticing: on 2026-09-22 flight/geometry.py brought numpy and scipy
  into the agent, the Windows installer grew from ~32 MB to 65.3 MB, and
  Supabase refused it (HTTP 400; the upload limit is 50 MB). The macOS .dmg,
  46 MB, still fit — barely. The same day `pnpm sidecar` started failing under
  cmd.exe, so Windows never got that far again. The owner chose terminal
  installs over paying for a bigger limit or moving the files.
- Every machine builds its own. That is also what gives an Intel Mac an Intel
  agent: PyInstaller freezes for the CPU of the Python running it, so an
  Apple-silicon build could never have served one.
- CI proves the install rather than producing anything. A green run on a
  machine means "those three lines give a person on this machine an
  installed app" — including that the agent stops when its window closes.
- One command for every OS, in Node (which pnpm needs anyway). A bash script
  and a PowerShell twin would drift; the old bash build script is what broke
  Windows.
- install.mjs refuses to replace a copy that is running, and never kills it:
  that copy may be flying. Closing it lands the drone and ends the session.
- The .dmg is not built. Tauri makes it through Finder (AppleScript), which
  is slow and fails without a logged-in desktop, and nothing uses it now.


INVARIANTS

- Neither half cross-compiles. PyInstaller freezes for the platform and CPU it
  runs on and Tauri bundles for the platform it runs on. That is why the
  matrix has four runners, and why macos-15-intel — GitHub's Intel image for
  public repositories — is in it.
- EVERY RUNNER SIGNS IN FOR REAL after installing (check_sign_in.py), and
  Linux also validates its installed files and menu entry. The Linux runner
  installs Tauri's prerequisites first — the same list setup.mjs prints.
- The sidecar is verified before Tauri bundles it (build_sidecar.py runs
  verify_sidecar.py). A frozen agent that cannot load libusb still builds and
  still launches — it fails only when a radio is plugged in, on a user's desk.
- A locally built app requires the macOS it was built on or newer, whatever
  Info.plist says: the agent bundles the build machine's libraries. Measured
  2026-09-25 on an M-series Mac with Homebrew's Python: several bundled dylibs
  (openssl, liblzma, libusb) have a minimum of macOS 26.0. Harmless when the
  machine installs for itself; wrong for handing the .app to another Mac.
- The builds are unsigned. A Mac that builds the app itself does not
  quarantine it, so Gatekeeper does not ask; Windows does not warn for a
  program it built and installed itself either.


KNOWN DIVERGENCE (2026-09-25)

- /apps still offers downloads from the old bucket, which holds the last
  builds published: macOS 2026-09-24, Windows 2026-09-21 — behind main and
  without this work. The setup guide no longer does: on 2026-09-27 the owner
  said to drop the bundled download and give the install instructions only,
  so its "Install the CropWatcher app" step is gone (live 2026-09-28 — see
  ../frontend/site-pages-and-views.txt for the stored copy that hid it).
  /apps itself has not been decided.
- The GitHub Actions secrets SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY are
  no longer used by anything, and the latter bypasses RLS. The owner should
  delete them (CLAUDE.md, "Three things only the project owner can do").
