--------------------------------------------------------------------------------
1. WHAT IT IS
--------------------------------------------------------------------------------
Every screen fits every width it can be shown at, in both themes, with nothing
squeezed, overlapping, clipped or scrolling the page sideways. The owner asked
for it three times — "responsive everywhere, small screens first", "the nav
should be a hamburger", and "make the right side very responsive — the tabs
are getting squeezed" — so it is a rule, not a request.

--------------------------------------------------------------------------------
2. WHERE IT LIVES
--------------------------------------------------------------------------------
desktop/src/measure.ts        the measurement: overflow per element
desktop/src/harness.tsx       every page with worst-case data; ?measure=1,
                              ?theme=light|dark, ?only=<section>, ?map=2d|3d,
                              ?selftest=1
desktop/src-tauri/tauri.conf.json   the window's minimum width, 720 px

--------------------------------------------------------------------------------
3. THE RULE
--------------------------------------------------------------------------------
• MEASURE AT THESE WIDTHS, IN BOTH THEMES, BEFORE CALLING UI WORK DONE:
    desktop app   720 · 900 · 1024 · 1280 · 1600 px   (720 is the window's
                  minimum; 1024 is where the Auto monitor squeezed)
    website       390 · 768 · 1024 · 1440 px          (a phone, a tablet, a
                  laptop, a desktop — the site is opened on phones)
  Desktop: the harness at each width with ?measure=1 and each ?theme, plus
  ?selftest=1 once — it must FAIL, or the measurement is not measuring.
  Report the counts. Web: a browser at each width, until a tool exists.
• LAY OUT BY THE CONTAINER'S WIDTH, NOT THE WINDOW'S. A panel sits in split
  columns, full-screen overlays and stacked layouts; the window's width says
  nothing about its own. Use Tailwind's @container / @md: / @4xl: (v4, built
  in). Window breakpoints (sm:, lg:) only for the page's own frame.
  Measured failures this prevents: the battery test's `sm:grid-cols-2` in a
  250 px column ("M1 passed" over "M2 failed"); the attitude readouts'
  two columns beside the instrument in a 294 px monitor.
• NOTHING IS SQUEEZED BELOW ITS CONTENT: things WRAP (a tab strip's actions
  drop under the tabs), then SCROLL SIDEWAYS INSIDE THEIR OWN BOX (the tabs
  themselves), never overlap. min-w-0 on flex and grid children that hold
  text; w-full min-w-0 on a <select>, which is otherwise as wide as its
  longest option.
• SMALL SCREENS FIRST: the thing an operator must reach comes first when
  columns stack (the vitals and Land above the flow), and a side menu folds
  into a drawer rather than shrinking.
• EVERY THEME, ALWAYS: tokens only (CLAUDE.md "Design tokens"); no colour
  claimed to pass contrast without measuring it against its background.

--------------------------------------------------------------------------------
4. INVARIANTS
--------------------------------------------------------------------------------
• A canvas (the Scene, the 3-D room map) is invisible to the DOM measurement:
  screenshot it at the widths as well (?only=<section>).
• A fixed full-screen overlay sits over the whole harness page; measure it in
  its own section (?only=full) so it does not hide the others.
